# T.GIT — Полноэкранное адаптивное веб-приложение для Android

**T.GIT** — это легкое, полностью полноэкранное Android-приложение формата WebView-оболочки (мини-приложения), которое открывает указанный в конфигурации сайт как самостоятельное нативное приложение без браузерного интерфейса и без запросов каких-либо пользовательских разрешений. Архитектура сразу адаптирована под смартфоны, складные устройства, планшеты и поворот экрана без потери состояния страницы.

---

### Решения пользователя и важные уточнения

> [!IMPORTANT]
> Все ключевые требования из вашего запроса и ответов зафиксированы ниже и будут применены при реализации.

- **Название и стартовая ссылка**: Приложение называется **T.GIT**. В коде выделен единый конфигурационный объект, где по умолчанию указана ссылка `https://www.google.com` — вы сможете заменить её на свой адрес в одну строку.
- **Чистый полноэкранный режим**: Верхняя панель навигации и адресная строка полностью отсутствуют. Сайт занимает весь экран (edge-to-edge), а системные вырезы камеры и жесты навигации корректно учитываются через безопасные отступы.
- **Стандартный современный WebView**: Используется чистый движок Android WebView с поддержкой JavaScript, DOM Storage, адаптивной верстки и темной темы без лишних JS-мостов.
- **Единый сайт**: Навигация жестко ограничена доменом настроенного сайта (включая его поддомены и служебные редиректы внутри него), чтобы приложение оставалось цельным мини-приложением одного ресурса.
- **Нулевые разрешения (Zero Runtime Permissions)**: Приложение не запрашивает у пользователя никаких разрешений (ни камеры, ни геолокации, ни памяти, ни уведомлений).
  - *Техническое примечание*: Для загрузки страниц из сети Android требует декларацию системного права `INTERNET` в манифесте — это обычное установочное разрешение, которое выдается системой автоматически при установке и **никогда не показывает пользователю диалоги запроса**.

### 1. Обзор и ключевая концепция

- **Что делает приложение**: При запуске пользователь сразу видит аккуратный короткий сплэш-оверлей с брендингом **T.GIT**, пока загружается стартовый URL, после чего веб-интерфейс плавно раскрывается на весь экран.
- **Для кого**: Для пользователей, которым нужен быстрый, чистый и привычный доступ к конкретному веб-сервису прямо с рабочего стола Android без рамок браузера.
- **Ключевая ценность**:
  - Сайт ощущается как полноценное нативное приложение.
  - Поворот экрана, изменение размера окна или раскрытие складного смартфона не сбрасывают открытую страницу.
  - Отсутствие сети не превращается в стандартную системную ошибку WebView — вместо нее отображается аккуратный адаптивный экран с кнопкой повторной загрузки.

### 2. Пользовательский опыт и визуальный дизайн

- **Основные пользовательские сценарии**:
  1. **Первый запуск**: Появляется минималистичная фирменная заставка **T.GIT** поверх глубокого фона темы (поддержка светлой и темной системной темы). Как только первый экран сайта готов, заставка плавно исчезает.
  2. **Работа с сайтом**: Пользователь взаимодействует с веб-приложением в полном экране. В самом верху у границы безопасной зоны отображается ультратонкая (2 dp) линия прогресса во время переходов между страницами, которая исчезает после 100% загрузки.
  3. **Жест обновления и кнопка «Назад»**: Системная кнопка/жест «Назад» возвращает на предыдущую страницу внутри истории сайта, а на стартовой странице закрывает приложение. При свайпе вниз в верхней части страницы (когда скролл страницы равен 0) срабатывает плавный pull-to-refresh.
  4. **Потеря соединения / ошибка загрузки**: Если интернет недоступен или адрес не отвечает, вместо стандартной белой страницы Chromium показывается нативная карточка состояния с понятным сообщением на русском языке и кнопкой «Обновить».
  5. **Выбор файлов в веб-формах (без разрешений)**: Если на будущем сайте встретится загрузка изображения или файла (`<input type="file">`), используется встроенный системный диалог выбора файлов Android, который работает полностью без разрешений на доступ к памяти.

- **Визуальная идентичность и тема**:
  - *Стиль*: Техничный минимализм — высокий контраст, чистая геометрия и отсутствие визуального шума, чтобы ничто не отвлекало от самого сайта.
  - *Цветовая палитра (Material 3)*:
    - Светлая тема: глубокий графитовый акцент (`#18181B`), чистый светлый фон (`#FAFAFA`), электрический синий/индиго-акцент (`#2563EB`) для индикатора загрузки и кнопки повтора.
    - Темная тема: глубокий темный фон (`#0B0D12`), мягкая поверхность карточки (`#151922`), яркий акцент (`#60A5FA`), светлый текст (`#F4F4F5`).
    - Тема нативной оболочки автоматически синхронизируется с темой системы и передает настройку темного режима в WebView.
  - *Иконка приложения*: Создается кастомная адаптивная иконка **T.GIT** вместо стандартной иконки Android.

- **Адаптивность под все устройства**:
  - *Смартфоны с вырезами (notch / punch-hole)*: Режим `enableEdgeToEdge()` с безопасными отступами `WindowInsets.safeDrawing` гарантирует, что верхняя и нижняя части сайта не перекрываются камерой или жестовой полосой навигации.
  - *Планшеты, складные экраны и ландшафт*: Нативные экраны (заставка, экран ошибки сети) ограничиваются максимальной шириной `480 dp` и центрируются по сетке `WindowSizeClass`, а сам WebView автоматически подстраивает ширину viewport без перезагрузки страницы при смене конфигурации экрана.

### 3. Ключевые продуктовые и технические решения

- **Управление навигацией и «Единый сайт»**:
  - *Выбранный подход*: Проверка хоста в `WebViewClient.shouldOverrideUrlLoading`. Навигация разрешается внутри базового домена целевой ссылки (включая поддомены и `www`). Ссылки на сторонние домены блокируются внутри основного полотна с коротким ненавязчивым уведомлением (Snackbar), чтобы приложение строго оставалось в рамках одного сайта. При необходимости поведение для конкретных доменов (например, OAuth-авторизации) легко настраивается списком исключений в конфигурации.
  - *Почему*: Обеспечивает целостность мини-приложения и гарантирует, что пользователь не «уйдет» из оболочки на сторонние ресурсы.

- **Сохранение состояния при поворотах и смене размера экрана**:
  - *Выбранный подход*: Обработка конфигурационных изменений (`orientation`, `screenSize`, `screenLayout`, `smallestScreenSize`) на уровне Activity + сохранение/восстановление `Bundle` состояния WebView через `ViewModel` / `rememberSaveable`.
  - *Почему*: При повороте телефона или раскрытии складного устройства страница не перезагружается заново, сохраняя заполненные формы и позицию прокрутки.

- **Персистентность и хранилище**:
  - *Выбранный подход*: Нативная база данных не требуется. Весь локальный кэш, cookies и `localStorage` самого сайта управляются стандартными механизмами WebView (`CookieManager`, `domStorageEnabled = true`), чтобы авторизация на сайте сохранялась между запусками приложения.

### 4. Техническая архитектура и потоки состояний

```
┌──────────────────────────────────────────────────────────────────────┐
│                       AppConfig (Единая точка)                       │
│   TARGET_URL = "https://www.google.com"  |  ALLOWED_ROOT_DOMAIN      │
└──────────────────────────────────┬───────────────────────────────────┘
                                   │
                                   ▼
┌──────────────────────────────────────────────────────────────────────┐
│                      MainActivity (Edge-to-Edge)                     │
│   Отслеживание WindowInsets (вырезы/панели) + ConfigChanges          │
└──────────────────────────────────┬───────────────────────────────────┘
                                   │
                                   ▼
┌──────────────────────────────────────────────────────────────────────┐
│                    MiniAppViewModel (StateFlow)                      │
│   Состояние: LoadingProgress | IsInitialLoad | CanGoBack | Error     │
└──────────────────────────────────┬───────────────────────────────────┘
                                   │
          ┌────────────────────────┼────────────────────────┐
          ▼                        ▼                        ▼
┌──────────────────┐    ┌─────────────────────┐   ┌──────────────────┐
│  WebViewContainer│    │ TopProgressOverlay  │   │  FallbackViews   │
│  • JS & Storage  │    │ • Линия загрузки    │   │ • Сплэш T.GIT    │
│  • Domain Guard  │    │   (2 dp, скрывается │   │ • Экран офлайна  │
│  • BackHandler   │    │   при 100%)         │   │   с кнопкой      │
│  • PullToRefresh │    │                     │   │   «Обновить»     │
└──────────────────┘    └─────────────────────┘   └──────────────────┘
```

- **Состояния UI (State Mapping)**:
  - `isInitialLoading`: Пока первая страница не достигла готовности (или до первого успешного `onPageCommitVisible`), отображается анимированная заставка **T.GIT**, скрывающая «мигание» белого экрана при старте.
  - `loadProgress (0..100)`: Обновляется из `WebChromeClient.onProgressChanged` и управляет плавной шириной и видимостью верхней полосы прогресса.
  - `errorState (null | WebError)`: Заполняется при сбое основного фрейма (`onReceivedError` с `isForMainFrame == true`), скрывает битую системную заглушку WebView и выводит нативный адаптивный экран ошибки с кнопкой повторной загрузки (`webView.reload()`).
  - `canGoBack`: Синхронизируется при каждой смене URL; `BackHandler` перехватывает системный жест «Назад» только когда `canGoBack == true`, обеспечивая естественный возврат по истории сайта или выход из приложения.
